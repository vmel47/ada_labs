# ADA Lab contributor entry point

Use English for source and documentation, explicit UTF-8 I/O, and Russian explanations when the owner requests them. Read [README.md](README.md), [architecture](docs/architecture.md), and [acceptance](docs/acceptance.md), then only the relevant source.

The current coding chat supplies development and independent criticism. Do not add an AI process launcher, copy account credentials, require WSL/Docker, or start paid execution. Use one Lead and one independent Reviewer; no nested delegation. Register real observer/tool references, preserve missing evidence as BLOCKED, and never substitute model claims for actual application checks.

Keep production ADA unchanged during experiments. Candidate edits, application workspaces, raw evidence and local records belong under ignored `.lab/`. The evaluator is trusted source, while generated application code runs only after native isolation probes. An evaluator edit invalidates its calibration. Public tests are calibration assets, never secret holdouts.

Before delivery run `python -m unittest discover -s tests -v`, native calibration, and an actual stable/candidate trial when capabilities permit. Obtain independent behavior and exact-source review. Publish only sanitized source and conclusions to the existing `ada_labs` remote; no force pushes, submodules, workflows, raw logs or secrets.
