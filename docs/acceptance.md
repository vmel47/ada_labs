# ADA Labs acceptance, v3

Source: owner's 2026-10-28 Autonomous Research, Benchmark Suites and Continuous ADA Optimization specification. It supersedes the earlier current-chat-only/single-task scope and specifically authorizes investigating controlled subscription CLI execution. Historical experiments retain their original acceptance and comparison policies; this document does not regrade them.

- C1: Canonical repositories and existing experiments preserved. Production ADA remains clean and unchanged; no automatic production promotion, Issues, Actions, paid API or unrelated services.
- C2: `Run.bat` checks/bootstrap local Python and opens a standalone loopback browser application. Ordinary research, model/suite selection, experiments, pause/resume, history and evidence inspection use real backend actions, not terminal handoffs.
- C3: Extensible task adapters declare capabilities. Exact SHA-256 file manifests cover task/starter/criteria/evaluator/UX inputs. Ordered multi-task suite identities include exact task revisions and evaluation policy; incompatible snapshots never mix.
- C4: Campaign fingerprints cover suite, explicit development and Reviewer profiles (model, effort, provider, runtime, relevant settings) and comparison policy. Display names are not identities; Medium/High are separate campaigns. Candidate revisions create trials within a campaign.
- C5: Structured global ideas include mechanisms, applicability, sources/dates, independent objections, confidence, transparent research-priority rubric, scope and related history. Research actually generates and critiques multiple hypotheses. Unsupported live retrieval is recorded honestly.
- C6: Research controls are separate from experiment controls. Reviewed ideas survive early research stop. Ranked candidates execute sequentially while resources permit; unstarted ideas remain retained.
- C7: Trials freeze Stable/candidate sources and profiles, independently review candidate changes, run cheap checks and develop actual applications from clean starters. Separate runtime sessions provide independent criticism/review; no developer self-acceptance.
- C8: Native probes precede generated code. Worker tools cannot write trusted Lab/evaluator/evidence/production or read private account files, and generated code cannot use the network. CLI authentication remains in its supported store. CLI worker/descendant lifetime is tied to the controller.
- C9: Actual handler/SQLite and real browser journeys verify the unchanged Repair Queue ten mandatory criteria plus independent selected checks and desktop/mobile visual review. Source review alone is insufficient. Missing capabilities remain BLOCKED.
- C10: Every required suite task retains separate outcomes. Missing/failed tasks cannot disappear behind sums or averaged quality scores. Quality gates precede observed tokens, autonomy and secondary time diagnostics.
- C11: Direct runtime events supply available input/output/cache token counts and session IDs, including failed attempts. Research/candidate work, benchmark Lead/Reviewer/corrections and deterministic external evaluation remain separately inspectable. Quota windows, tokens, estimates and configured budgets are different units; unavailable telemetry is null.
- C12: Whole-suite admission/reservation is atomic, includes review/correction allowance and configurable reserve. Reliable insufficient limits prevent launch. Stage/time bounds do not imply hard token spending enforcement or authorize paid fallback.
- C13: Durable checkpoints survive pause, close/restart and coding-session changes. Completed work is not rerun automatically; uncertain work requires explicit reconciliation/resume. Immutable inputs, source-bound receipts, failed attempts and unknown consumption remain retained.
- C14: Compact trial/campaign summaries reference full protected evidence. Local export has complete source/evidence integrity manifests. Public Git contains only sanitized source and conclusions; no credentials or raw run logs.
- C15: Provisional Leader, non-dominated alternatives and confirmed Champion remain distinct and campaign-specific. Exact-source confirmation uses fresh application contexts and varied order under a predefined policy; one favorable pair does not confirm a Champion.
- C16: Local UI enforces loopback Host/Origin/CSRF boundaries. Generated HTML is never served as privileged Lab UI; evidence/source downloads do not execute application code on the host.
- C17: Demonstrations cover a real one-task campaign through the launcher/UI, deterministic three-task scheduling/identity/aggregation, actual pause/restart/resume, model mismatch/unknown telemetry/budget integrity and independent source/behavior review. Required regression tests, native calibration and a new real stable/candidate trial precede a completion claim.

Unsupported specialized task environments and untested platform/model combinations must be described, not presented as working. Smart-contract signing, transfers and production broadcasting remain prohibited without separate explicit authorization. The local JSON trust model protects against sandboxed workers and accidental mixing; it does not authenticate a malicious maintainer who can edit trusted source and state.
